# RailFeas — 노선 타당성 분석 시뮬레이터

지도에 노선을 그리면 **건설비 · 예상 이용객 · B/C**를 산출하고, 그 수요에 맞는 교통수단과
정차역을 추천하는 웹 서비스. 예비타당성조사(KDI PIMAC) 방법론을 축소·근사한
개인 프로젝트(8주, 단독 / 학번 202245079 신선호).

핵심 질문은 하나다 — **"이 구간에 지하철이 과한가?"**
같은 노선을 지하철·경전철·트램·BRT·복선전철 × 지하/고가/지상으로 모두 계산해 나란히 보여 준다.

```
10.97km 서울 도심 노선 · 주변 인구 13.1만 · 예상 이용객 10.2만/일
  BRT 고급형 지상   617억   B/C 6.72
  경전철    고가  5,706억   B/C 1.13
  지하철    고가  9,041억   B/C 0.89   ⚠ 과잉 투자 검토
  지하철    지하 1조5,172억  B/C 0.53   ⚠ 과잉 투자 검토
```

## 이 프로젝트가 신경 쓰는 것

숫자보다 **출처**다. 모든 기준값은 실측·지침값과 가정값을 구분해 적고, 근거가 없으면
경고를 띄우지 않는다. 관리자 화면에서 값을 고칠 때도 근거를 함께 받는다.

| 구분 | 값 | 근거 |
|---|---|---|
| 시간가치 7,231원/인·시 | 지침 | 교통시설 투자평가지침 제7판 표 4-44 (CPI 2025년 환산) |
| 할인율 4.5% / 3.5%, 분석기간 40년 | 지침 | 같은 지침 6.2.1 · 6.2.2 (철도사업 기준) |
| 표정속도 중전철 32.4 / 경전철 29.3 / 복선전철 47.6 | 실측 | 서울·부산교통공사 공공데이터, 인천교통공사·신분당선 공식 |
| 전환 전 수단 21.3km/h | 실측 | 국가지표체계 6대 광역시 시내버스 중앙값 (승인통계) |
| 첨두율 0.0987 | 실측 | 서울 613개 역 시간대별 승하차 3개월 |
| 단면 환산계수 0.3165 | 실측 | 서울교통공사 혼잡도(교통카드 O/D 재차인원) |
| 수요 하한 중전철 20,000 | 실측 | 실제 운영 노선 최저 단면(8호선 20,403) |
| 트램 22.1km/h | **설계값** | 대전 2호선 미개통 |
| **BRT 2종 속도** | **가정값** | 공식 실측을 찾지 못했다 (CLAUDE.md 에 조사 경로 기록) |

비용·수요 모델은 회귀로 직접 추정했다.

- **비용** `log(사업비) = 6.867 + 0.650·log(연장) + 0.575·지하비율 + 0.272·log(역수) + 수단더미`
  — 실사례 381건 중 A등급 38건, R² 0.889, 교차검증 **1.25배**
- **수요** `log(일이용객) = 2.608 + 0.437·log(인구) + 0.283·log(종사자) + 1.080·log(환승노선) − 0.012·도심거리`
  — 서울·수도권 514개 역, R² 0.551, 교차검증 **1.75배**

## 기능

지도 노선 설계 · 인구밀도 3D · 비용 산출 · 수요 추정 · B/C · 수단 추천 ·
정차역 자동 배치 · 시나리오 비교 · 관리자 기준값 CRUD

## 실행

```bash
cp .env.example .env            # 키는 .env 에만 넣는다 (저장소에 올리지 말 것)
docker compose up -d            # MySQL(호스트 3307) + Redis, 첫 기동에 스키마·시드 자동 적재
cd backend && ./mvnw package && java -jar target/railfeas-0.1.0.jar
cd frontend && npm install && npm run dev      # http://localhost:5173
```

`DB_PASSWORD` 는 `.env` 값을 compose 와 백엔드가 함께 읽는다.
VWorld 키(`frontend/.env`)가 없으면 OpenFreeMap 타일로 자동 대체된다.

## 데이터 재생성

```bash
pip install -r etl/requirements.txt
python etl/etl.py               # 원본 → reference_line + S2
python etl/cost_model.py        # 비용 회귀 → S5
python etl/seoul_ridership.py   # 승하차·역 좌표
python etl/sgis_population.py   # 집계구 인구·종사자
python etl/demand_model.py      # 수요 회귀 → S6
python etl/seoul_peak.py        # 첨두율
python etl/seoul_congestion.py  # 단면 환산계수
docker compose down -v && docker compose up -d   # 시드를 바꿨으면 볼륨을 비워야 다시 적재된다
```

## 한계 (보고서에 명시)

- 통행배정모형·OD 설문 대신 인구밀도 기반 회귀 근사 → **상대 비교 지표**로만 의미
- 편익은 통행시간 절감 중심 (차량운행비·사고·환경비용 제외)
- BRT의 도로 용량 잠식 미반영 — BRT의 B/C 가 유리하게 나온다
- 인구는 거주 인구 기준이라 업무지구(강남·종로)는 낮게 잡힌다
- 규제 구역 좌표·반경은 근사치 — "확인 필요"로만 안내한다

# RailFeas — 노선 타당성 분석 시뮬레이터 

[![CI](https://github.com/sinsun030508/Map-based-Urban-Rail-Feasibility-Simulator/actions/workflows/ci.yml/badge.svg)](https://github.com/sinsun030508/Map-based-Urban-Rail-Feasibility-Simulator/actions/workflows/ci.yml)

지도에 노선을 그리면 **건설비 · 예상 이용객 · B/C**를 산출하고, 그 수요에 맞는 교통수단과
정차역을 추천하는 웹 서비스. 예비타당성조사(KDI PIMAC) 방법론을 축소·근사한
개인 프로젝트(8주, 단독 / 학번 202245079 신선호).

핵심 질문은 하나다 — **"이 구간에 지하철이 과한가?"**
같은 노선을 지하철·경전철·트램·BRT·복선전철 × 지하/고가/지상으로 모두 계산해 나란히 보여 준다.

```
12.28km 서울시청~잠실 · 노선 둘레 인구 36.3만 · 예상 이용객 29.7만/일        (2026-11 계산)
  광역급행  고가     6,556억   B/C 6.71  ← 추천
  BRT 고급형 지상      595억   B/C 5.24   (이용객 10.3만 — BRT 보정)
  복선전철  고가     8,384억   B/C 3.82
  지하철    고가   1조1,152억   B/C 1.87   ⚠ 과잉 투자 검토
  경전철    고가     7,049억   B/C 1.25   (이용객 15.7만 — 경전철 보정)
  지하철    지하   1조7,743억   B/C 1.18   ⚠ 과잉 투자 검토
```

**절대값이 아니라 순위를 읽는다.** 수요는 인구·종사자로 한 번 추정하고, 실측이 있는 수단만 그 행을 줄인다 — 경전철 0.53배(우이신설·신림·부산 4호선·대구 3호선),
BRT 0.35배(세종 BRT 축, 행복청 2024). 트램은 국내 운영 노선이 없어 **보정하지 못했다.** 이용객은 역 승차·하차를 합한 수라 한 통행을 두 번 세므로,
편익은 그 0.745배(노선 이용자 = 승차 + 환승유입, 서울교통공사 실측)로 센다. 11-08 까지는 이 둘이 빠져 BRT 가 B/C 20 으로 추천됐었다.

B/C 의 비용은 건설비뿐이라 운영비만큼 **높게** 나온다(KDI 예타 사례로 약 0.75~0.79배) — 아래 한계 참고.

## 이 프로젝트가 신경 쓰는 것

숫자보다 **출처**다. 모든 기준값은 실측·지침값과 가정값을 구분해 적고, 근거가 없으면
경고를 띄우지 않는다. 관리자 화면에서 값을 고칠 때도 근거를 함께 받는다.

| 구분 | 값 | 근거 |
|---|---|---|
| 시간가치 7,231원/인·시 | 지침 | 교통시설 투자평가지침 제7판 표 4-44 (CPI 2025년 환산) |
| 할인율 4.5% / 3.5%, 분석기간 40년 | 지침 | 같은 지침 6.2.1 · 6.2.2 (철도사업 기준) |
| 표정속도 중전철 32.4 / 경전철 29.3 / 복선전철 47.6 / 광역급행 91.8 | 실측 | 서울·부산교통공사 공공데이터, 인천교통공사·신분당선 공식 |
| 전환 전 시간 — 시내버스 21.3km/h 와 기존 도시철도 중 빠른 쪽 | 실측 | 국가지표체계 6대 광역시 시내버스 중앙값(승인통계), 기존 노선은 공표 표정속도 |
| 1인 통행거리 13.6km (절감을 이 거리까지만 센다) | 실측 | 서울시 2019 교통 빅데이터 — 지하철 1회 이동 |
| 첨두율 0.1159 | 실측 | 서울 1~8호선 평일 21일(2024-11) 첨두 1시간 비중 |
| 단면 환산계수 K = min(0.395, 10.06 ÷ 연장km) | 실측 | 서울교통공사 혼잡도(교통카드 O/D 재차인원), 2·5·6·8호선 |
| 수요 하한 중전철 20,000 / 경전철 4,700 | 실측·추정 | 실제 운영 노선 최저 단면(8호선 20,403 / 우이신설·신림 외삽) |
| 트램 22.1km/h | **설계값** | 대전 2호선 미개통 |
| **BRT 2종 속도** | **가정값** | 세종 BRT 를 직접 쟀으나 대표성 조건을 못 넘어 유지 (research-log) |

비용·수요 모델은 회귀로 직접 추정했다.

- **비용** `log(사업비) = 6.910 + 0.663·log(연장) + 0.515·지하비율 + 0.257·log(역수) + 수단더미`
  — 실사례 381건 중 A등급 38건, R² 0.887, 교차검증 **1.25배** (지하비율 17건 OSM 실측)
- **수요** `log(일이용객) = -2.195 + 0.528·log(인구) + 0.615·log(종사자) - 0.638·경전철`
  — 운영 노선 34개(수도권 26 + 대전·부산·대구 8), R² 0.885, 교차검증 **1.34배**. 인구·종사자는 선 둘레 1km 를 겹침 없이 센다.
  경전철 항(×0.53)은 경전철 행에만 쓴다. BRT 행은 세종 BRT 축 실측에 맞춘 ×0.35, 트램은 자료가 없어 그대로다.
  편익은 이용객(역 승하차 합) × 0.745 = 노선 이용자 수로 센다

## 기능

지도 노선 설계 · 인구밀도 3D · 비용 산출 · 수요 추정 · B/C · 수단 추천 ·
정차역 자동 배치 · 기존 도시철도·KTX 비교 · 호수 우회 제안·물 위 구간 표시 ·
산 구간 판정(35‰ — 뚫는 안과 돌아가는 안의 건설비·시간 비교) · 건설비 구성·역별 이용객 차트 ·
시나리오 비교 · 소셜 로그인(Google·카카오) · 관리자(기준값·단가·회원·통계) · API 문서(Swagger) ·
Docker 배포 묶음(`docs/deploy.md`)

## 실행

```bash
cp .env.example .env            # 키는 .env 에만 넣는다 (저장소에 올리지 말 것)
docker compose up -d            # MySQL(호스트 3307) + Redis, 첫 기동에 스키마·시드 자동 적재
cd backend && ./mvnw package && java -jar target/railfeas-0.1.0.jar
cd frontend && npm install && npm run dev      # http://localhost:5173
```

`DB_PASSWORD` 는 **직접 정해 `.env` 에만** 넣는다 — compose 와 백엔드가 함께 읽고, 기본값이 없어 비어 있으면 둘 다 멈춘다.
`JWT_SECRET` 도 같다(`python -c "import secrets; print(secrets.token_hex(32))"`).
VWorld 키(`frontend/.env`)가 없으면 OpenFreeMap 타일로 자동 대체된다.
API 문서는 `.env` 에 `SWAGGER_ENABLED=true` 를 넣고 백엔드를 켜면 `http://localhost:9090/swagger-ui.html` 에서 본다(기본은 닫혀 있다).
소셜 로그인(Google·카카오)은 **키가 있는 공급자만** 켜진다 — `.env` 에 `KAKAO_CLIENT_ID`(앱의 REST API 키,
시크릿을 켰으면 `KAKAO_CLIENT_SECRET` 도)나 `GOOGLE_CLIENT_ID`·`GOOGLE_CLIENT_SECRET` 을 넣고 백엔드를 다시 띄운다.
공급자 콘솔에는 리다이렉트 주소로 `http://localhost:9090/login/oauth2/code/kakao`(Google 은 `…/google`)를 등록한다.
카카오는 「카카오 로그인」 을 켜고 동의 항목에 **닉네임**을 둔다(이메일은 요청하지 않는다). 키가 없으면 버튼이 안 보인다.

## 데이터 재생성

```bash
pip install -r etl/requirements.txt

python etl/cost_model.py        # 비용 회귀 → S5
python etl/seoul_ridership.py   # 승하차·역 좌표
python etl/sgis_population.py   # 집계구 인구·종사자
python etl/demand_model.py      # 수요 회귀 → S6
python etl/seoul_peak.py        # 첨두율
python etl/seoul_congestion.py  # 단면 환산계수
python etl/osm_water.py         # 호수·강 수면 영역(OSM)
python etl/dem_tiles.py         # 지형 타일(AWS Terrain Tiles z11, 1,312장 · 약 36MB) — 산 구간 판정, 없으면 기능이 꺼진다
docker compose down -v && docker compose up -d   # 시드를 바꿨으면 볼륨을 비워야 다시 적재된다
```

## 테스트 

```bash
cd etl && python -m pytest      # 298개 — 원자료 파서·측정 규칙·문서 일치·비밀값
cd backend && ./mvnw test       # 223개 — 계산 로직과 판정 규칙 (실행 중인 백엔드는 끄고 돌릴 것)
cd frontend && npm test         # 53개 — 뜻이 갈리는 화면 표기·훅 순서·401 처리·소셜 콜백·산 구간 문구·회원 관리 규칙·지도 준비 기준·비용 구성·역별 이용객·경전철 이용객 표기 (node --test, 의존성 없음)
```

- **GitHub Actions**(`.github/workflows/ci.yml`)가 푸시·PR 마다 세 묶음을 깨끗한 환경에서 돌린다 — 저장소에 없는
  파일(`.env`·캐시)에 기댄 테스트를 잡는다. 백엔드는 `pom.xml` 대로 Java 17 이다
- **통과만 하는 테스트는 못이 아니다** — 규칙을 일부러 지워 보고 그 테스트만 깨지는지 확인한다
- `etl/test_docs_match_code.py` 는 문서의 숫자가 코드·자료와 맞는지 본다 — **위의 테스트 수도**
  (이 절이 「14건」 으로 한참 낡아 있었다)
- `etl/test_no_secrets.py` 는 비밀값이 저장소에 올라가지 않았는지 본다 — 이 PC 의 `.env` 값까지
- `./mvnw` 는 백엔드를 켜 둔 채거나 maven 내려받기가 끊기면 **조용히 아무것도 안 하고** 예전 보고서를
  남긴다. 받아 둔 maven 은 `~/.m2/wrapper/dists/*/*/bin/mvn -o`

## 한계 (보고서에 명시)

- 통행배정모형·OD 설문 대신 인구밀도 기반 회귀 근사 → **상대 비교 지표**로만 의미
- 편익은 통행시간 절감 중심 (차량운행비·사고·환경비용 제외)
- **비용은 건설비뿐** — 운영비·대체투자비가 빠져 B/C 가 높게 나온다(KDI 예타로 약 0.75~0.79배).
  수단마다 같은 근거가 없어(복선전철은 옛 지침 사례뿐, 트램은 예타 없음) 넣지 않았다
- 교량·하저터널 할증 없음 — 물 위·아래를 지나는 길이만 보여 준다
- BRT 속도는 가정값, 지하비율 40건 중 23건(공사 중·계획 노선)은 추정치
- BRT의 도로 용량 잠식 미반영 — BRT의 B/C 가 유리하게 나온다
- 인구는 거주 인구 기준이라 업무지구(강남·종로)는 낮게 잡힌다
- **수요 표본은 수도권 26 + 대전·부산·대구 8개 노선이다** — 장거리·광주 등 다른 지역은 외삽이다. 트램은 수요 자료가 없어 보정하지 못했다
- 산 구간의 터널비는 도심 지하 단가로 매긴 외삽이다 — 단가 표본에 산악 터널 노선이 없다
- 규제 구역 좌표·반경은 근사치 — "확인 필요"로만 안내한다

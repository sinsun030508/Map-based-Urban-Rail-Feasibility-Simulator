# 프론트엔드 화면 규칙

`frontend/` 아래를 만질 때만 로드된다. **화면에서만 쓰는 규칙**이 여기 있다.

API 응답 형식·관리자 CRUD 검증 규칙·낡은 결과 알림처럼 **백엔드와 공유하는 계약**은
`docs/engineering-notes.md` 의 「화면」·「B/C 산출」 절에 있다 — 백엔드 세션에서도 보여야
한다. (전에는 루트 `CLAUDE.md` 에 있었는데, 그 파일이 900줄까지 자라 100줄로 줄이면서
본문을 노트로 옮겼다.) 루트 `CLAUDE.md` 에는 **규칙과 값만** 남아 있다.

**`App` 의 훅은 이른 `return` 위에 둔다.** `App` 은 로그인·관리자·시나리오 비교 화면으로 일찍
`return` 한다. 그 아래에 훅을 두면 그 화면으로 갈 때 훅 개수가 줄어 **"Rendered fewer hooks"
로 화면이 통째로 깨진다** — 호수 우회의 `useEffect` 를 아래에 두어(10-26) **시나리오 비교·
관리자·로그아웃이 11-01 까지 깨져 있었다.** 그 화면들을 눌러 보지 않아 몰랐다 — 기능을 더하면
화면을 오가는 버튼까지 눌러 볼 것. `App.hooks.test.js` 가 소스 모양으로 막는다 — **모든 컴포넌트**를
훑는다(다른 컴포넌트에는 없음을 11-01 에 확인했다. 고치기 전 `App.jsx` 로 돌리면 그 줄을 짚고 실패한다).
관리자 화면(「기준값 관리」)은 시험 계정을 잠깐 ADMIN 으로 올려 열어 봤다 — 확인 뒤 USER 로 되돌린다

**로그인·가입(`/auth/`)의 401 만 세션 만료가 아니다 (`api/client.js`).** 이메일·비밀번호가 틀린
것이라 서버의 안내("이메일 또는 비밀번호가 올바르지 않습니다")를 그대로 띄운다. 전에는 401 을 모두
만료로 바꿔, 없는 계정으로 로그인하면 "로그인이 만료되었습니다" 가 떴다(11-04 화면 점검).
- **「토큰을 보냈을 때만 만료」 로 가르면 안 된다** — 처음 그렇게 고쳤다가 리뷰에서 걸렸다. 다른 탭에서
  로그아웃해 토큰만 사라진 화면은 토큰 없이 401 을 받는데, 그것도 만료다. 그렇게 가르면 로그인
  화면으로 안 내려가 **로그인된 척하는 화면**이 남는다(`client.test.js` 세 경우)
- 만료로 내려오면 **로그인 화면에 이유를 적는다**(`App` 의 `expired` → `LoginPage` 의 `notice`).
  직접 로그아웃하면 적지 않는다. 문장은 `SESSION_EXPIRED_MESSAGE` 한 곳에 있다
- **다시 로그인한 사람이 다르면 앞 사람의 작업을 비운다**(`App` 의 `lastUserId`) — 같은 사람이면
  그리던 노선을 남긴다. 안 비우면 앞 사람이 고치던 `editingId` 로 「수정 저장」 이 남의 시나리오에 가고,
  관리자 화면에서 끊긴 뒤 일반 사용자가 들어오면 **관리자 화면이 그려졌다** — 그래서 관리자 화면은
  `admin` 상태만이 아니라 **`user.role === 'ADMIN'` 일 때만** 그린다

**소셜 로그인은 `/oauth/callback#token=…` 으로 돌아온다 (`auth/oauthCallback.js`).** App 이 **주소에서 토큰부터
지우고**(`replaceState`) `/me` 로 닉네임·권한을 받아 이메일 로그인과 같은 `signedIn` 을 탄다. 버튼은
`/api/auth/providers` 가 준 것만 그린다 — 키가 없으면 0개다(누르면 404 라서).
- **`LoginPage` 의 안내는 나중에 바뀔 수 있다** — 처음 값(`useState(notice)`)만 보면 안 된다. 세션 만료는
  화면이 뜰 때 이미 정해져 있지만 소셜 실패(`#error=`·`/me` 실패)는 화면이 뜬 **뒤에** 온다. 처음엔
  `useState` 로만 받아 그 안내가 안 떴다(`useEffect([notice])` 로 고쳤다)
- **이미 로그인해 있을 때의 소셜 실패도 보여야 한다** — 실패는 `socialError`(로그인 화면)와 `error`(지도 패널)
  **둘 다**에 둔다. Google 로 로그인해 있는 창에서 카카오가 실패하자 로그인 화면이 안 떠 실패가 아무 말 없이
  사라졌고, 지도가 그대로라 「카카오 로그인 됐다」 로 보였다(11-05). 백엔드도 실패를 로그에 남긴다

**클릭은 정차역이 아니라 선형이다.** 첫 점은 출발, 마지막 점은 도착이고 가운데 점은 선이 꺾이는
경유점(작은 ◆)이다. 정차역은 계산 후 `StationPlanner`가 놓는다. 경유점에 번호(1, 2…)를 달았더니
"다음 클릭에 이전 도착지가 정차역이 된다"고 읽혔다 — 경유점에 역처럼 보이는 표시를 달지 말 것.

**결과 패널 폭(`.panel`)** `clamp(340px, 26vw, 500px)` — 넓은 화면에서 함께 커진다. 340px
고정이면 남는 폭을 지도(`flex:1`)가 다 먹어 **비교표가 어느 화면에서나 308px 에 눌린다**
(`복선전/철`, `20/분` 으로 접힘). 지도 설계만큼 결과 비교도 큰 화면이 필요하다.

**수단 이름은 `src/modeLabels.js` 한 곳에 있다.** 전에는 같은 표가 `CostTable`·`BcChart`·
`ComparePage`·`AdminPage` 네 벌로 복사돼 있어, 수단을 더하면 네 군데를 고쳐야 했고 하나를
빼먹으면 그 화면만 `EXPRESS_RAIL` 같은 코드를 그대로 보여 줬다. API 가 이름을 주지 않아
(응답은 `modeType` 코드만 싣는다) 화면이 이름을 갖는 것은 맞다 — 다만 한 벌이어야 한다.

- **DB `display_name` 과 일부러 다르다.** DB 는 정식 명칭 `광역급행철도` 를 남기고 화면은
  `광역급행` 을 쓴다 — 비교표 수단 칸이 **75px** 라 6자가 두 줄로 접힌다
- `MODE_LABEL_SHORT` 는 `BcChart` 전용이다. 이름 칸이 **84px 고정**이라 `BRT 고급형 지상` 은
  **잘리는 게 아니라 축 밖으로 삐져나간다**(10px 글자, 오른쪽 정렬)
- **비교표의 수단·구조 칸은 `white-space: nowrap` 이다.** `table-layout: auto` 는 가장 긴
  이름에 맞춰 칸을 잡아서, **이름 하나만 짧아져도 칸이 줄어 다른 이름이 대신 접힌다**
  (`광역급행철도`→`광역급행` 으로 줄였더니 75→68px 이 되어 `BRT 고급형` 이 두 줄이 됐다).
  B/C 칸에 여유가 있어 가져올 수 있다 — **위** 패널 폭과 같은 문제다
- **비교표는 수단과 구조를 한 칸에 적는다**(`지하철 지하`). 칸을 나눴더니 첫 칸만 읽혀
  "지하철이 두 번 나온다 — 중복 아니냐"는 반응이 실제로 나왔다(지하·고가 두 행이었다).
  막대 그래프·시나리오 비교도 같은 표기다
- **`td:first-child` 로 nowrap 을 걸면 안 된다.** `tfoot` 의 `colSpan=5` 설명 칸도 자기
  행의 첫 칸이라 함께 걸린다. 그 긴 문장이 한 줄로 펴지면서 표가 **1,463px** 로 부풀어
  324px 패널을 뚫고 나가고 **역·소요·건설비·B/C 칸이 통째로 화면 밖으로 밀렸다**.
  `thead th:first-child` · `tbody td:first-child` · `tfoot tr.existing td:first-child`
  **셋을 따로** 적는다 (기존 수단 행의 이름 칸은 접히면 안 되므로 거기만 다시 건다)

**기존 수단은 비교표의 `tfoot` 참조 행이다 (`existingOption`).** 전에는 표 **위**에
경고 문구로만 떠 있었다 — 서울~부산을 그리면 340km BRT 가 추천으로 올라오는데 "이미 KTX 가
있고 추가 건설비가 0" 이 표 밖에 있었다. **비교는 표에서 일어난다.**

- **`tbody` 가 아니라 `tfoot` 인 것이 핵심이다.** 계산 결과가 아니므로 정렬·'가장 싼 안'
  강조·행 클릭(정차역 그리기)에 끼어들면 안 된다
- **수단 칸에는 짧은 이름만**(`기존 KTX`·`기존 2호선`). 노선 목록(`KTX 경부선·호남선·
  전라선·경전선`)을 여기 넣으면 `table-layout: auto` 가 그 길이에 칸을 맞춰 **다른 수단
  이름이 대신 접힌다** — 위 폭 항목과 같은 문제다. 노선 목록·접근 거리는 아래 설명 줄로
- **소요시간 칸에는 「빠른 계통의 중앙값」 하나만** 넣는다(`existingOption.travelMin`).
  **한 열차의 시각을 적으면 안 된다** — 2026-10-20 서울~부산은 고속선 44편 143~176분
  (중앙 164)과 우회 11편 180~205분(중앙 198), **두 계통**이다. 갈리는 폭은 설명
  줄(`travelDetail`)이 받는다 — 좁은 칸에 네 숫자를 넣으면 아무도 안 읽는다.
  값은 `etl/korail_travel_time.py` 가 TAGO 「열차정보」에서 미리 받아 둔다
- **설명 줄의 단위도 분이다.** 칸이 `164분` 인데 설명이 `2시간 23분~2시간 56분` 이면
  읽는 사람이 둘을 잇지 못한다. 표의 신설안 행이 전부 분이라 **같은 단위여야 비교된다**
- **그 구간 자료가 없으면 0 이 아니라 빈 칸**이다. 0 이면 KTX 가 순간이동한 것처럼 보인다.
  **B/C 는 자료가 있어도 비운다** — 이미 있는 시설에 B/C 를 매기는 것은 신설안과 범주가
  다르다. 「못 구했다」와 「적으면 안 된다」를 한 문장에 섞어 적지 말 것
- 시나리오 비교(`ComparePage`)에는 「이미 있는 수단」 행으로 들어간다. 그 칸만
  **왼쪽 정렬**이다 — 나머지는 숫자라 오른쪽 정렬인데 여기는 문장이다

**빨간 노선은 그린 점만 잇지 않는다 (`geo/routeLine.js`).** `StationPlanner` 가 역을 선에서
**옆으로 최대 0.5km** 비켜 인구가 많은 쪽에 놓는데, 지도가 그린 점만 이으면 역이 선 밖에 떠
있고 **선은 가지도 않는 길**을 보여 준다. 비용·편익은 이미 돌아간 길이로 계산하므로
(`CostCalculator` 의 `routeKm = lengthKm + plan.detourKm()`) 지도만 직선이면 **화면과 숫자가
서로 다른 노선**을 말한다.

- **역만 이으면 안 된다.** 경유점을 찍어 꺾어 그린 노선에서 역이 둘뿐이면(복선전철·급행처럼
  역간격이 넓은 수단) 꺾임이 통째로 사라져 사용자가 그린 모양이 없어진다. 그린 꼭짓점과
  역을 **선 위 거리 순으로 엮는다** (`alongKm` 이 선분마다 수직으로 내려 위치를 잰다)
- 검산: 서울시청~사당 꺾은 노선에서 그린 길이 15.864km, 화면 선 16.017km, 건설비에서
  역산한 백엔드 `routeKm` 16.018km — **0.6m 안에서 맞는다**
- 비교표에서 **아무것도 안 고르면 그린 선 그대로**다. 수단을 바꾸면 역이 달라지므로
  선도 다시 그린다(`[points, stations]`)
- 패널의 km 는 **사용자가 그린 길이**이고 돌아간 몫은 안 더한다 — 그린 것과 계산된 것을
  가려 보여 주기 위해서다

**권장 연장을 넘는 수단은 기본으로 내세우지 않는다 — 네 곳이 같은 안을 가리켜야 한다.**
지도가 그리는 안(`App.jsx` 의 `shown`/`overLength`), 비교표에서 **굵게 강조하는 안**
(`CostTable` 의 `best`), 시나리오 비교의 **「추천안 B/C」·「추천안 건설비」**
(`ComparePage` 의 `bestOf`), 백엔드 추천(`CostCalculator.recommended`) 넷이다.

- **B/C 0(절감 시간 없음)인 안도 내세우지 않는다** — 판정은 `scenario/gainsNothing.js`
  한 곳에 있고 네 곳이 그것을 쓴다. 기존 KTX 를 편익 기준에 넣자 서울~부산 신설안이 전부
  0 이 됐는데 복선전철이 추천됐었다(지금은 KTX 가 기준에서 빠져 0 이 아니다 — 2호선을 따라
  그리면 7개가 0 이다). 전부 0 이면 **굵은 행도, 지도의 정차역도 없고**, 표
  위에 "추천할 신설안이 없습니다" 를 한 줄 적는다
- **B/C 0 행에는 꼬리표를 달지 않는다** — 숫자만 흐리게(`.muted`) 하고 이유는 표 위 한
  줄이 말한다. B/C 칸이 48px 라 `.tag`(block)가 숫자 밑으로 내려가 **짧은 「절감 없음」
  조차 7행을 두 줄로** 늘렸다(2호선을 따라 그리면 11행 중 7행이 0 이다). 그 한 줄은
  "기존 2호선보다 느림" 이라고 **단정하지 않는다** — 전환 전 시간은 시내버스와 기존 수단 중
  빠른 쪽이고, 짧은 노선은 역까지 걷는 몫 때문에 버스가 이길 수 있다. **KTX 는 이 문장에
  넣지 않는다** — 짧은 이동에 못 타 기준에서 빠지고, 접힌 설명에 그 이유를 따로 적는다
- **`ComparePage` 는 규칙을 다시 계산하지 말고 `recommendedMode` 를 따른다.** 전에는
  B/C 최고안을 그냥 집어서, 「추천 수단」은 광역급행인데 「최고 B/C」는 340km 짜리
  BRT 고급형이라고 적혀 **한 표가 두 안을 동시에 가리켰다.** 백엔드가 이미 거른 답이
  있는데 화면이 또 고르면 어긋난다 — 그래서 칸 이름도 「최고」가 아니라 「추천안」이다
- 서울~부산(340km)에서 **340km 짜리 BRT 고급형**이 B/C 최고라 굵게 찍히는데 지도는
  광역급행을 그리고 있었다 — **화면이 두 안을 동시에 가리킨 셈이다.** 표에는 그대로
  남긴다(선택을 막지 않는다). 권장 연장 안에 맞는 안이 하나도 없으면 맨 위를 쓴다 —
  강조가 사라지는 것보다 낫다

**운영비가 빠져 B/C 가 높게 나온다는 것을 B/C 옆에 적는다.** 비용에 건설비만 들어간다
(예타는 운영비·대체투자비를 더한다 — research-log 「운영비」). 비교표는 접히는 설명의
**요약 줄**에 「운영비를 넣지 않아 B/C가 높게 나옵니다」 를 올리고(접혀서 안 보이면 없는 경고다)
펼친 칸에 근거(경전철 예타 사례 약 0.78배)를, 시나리오 비교는 표 위 한 줄에 같은 말을 적는다.
수단마다 운영비 구조가 달라 **아직 계산에 넣지 않았다** — 값이 모이면 이 안내를 걷는다

**숫자 표기는 `src/format.js` 한 곳에 있다**(`money`·`people`·`bc`). **B/C 는 `bc()` 로만
찍는다** — 0 과 작은 양수를 가른다(0.002 → `<0.01`). 0.00 은 "아끼는 시간이 (거의) 없다" 는
뜻으로 흐리게 찍는데, 작은 양수까지 0.00 이면 둘을 구별할 수 없다(`npm test` 가 고정한다). `CostTable` 과
`ComparePage` 에 똑같은 것이 각각 복사돼 있었다 — 수단 이름을 `modeLabels.js` 로 모은
것과 같은 이유다.

**건설비 막대(`CostChart`)** 기존 수단이 **0** 으로 꽂히는 것이 요점이다. 표에도 `기존 KTX
… 0` 이 있지만 42조와 0 이 숫자로만 나란히 있으면 차이가 안 읽힌다.

- **B/C 차트에 섞지 않는다.** 축이 다른 두 측정을 한 그림에 넣으면 어느 막대가 무엇인지
  알 수 없고, 애초에 기존 수단은 **B/C 를 일부러 비워 뒀다**
- **기존 수단이 없으면 그리지 않는다** — 비용 순위는 표가 이미 말한다
- 기존 수단 줄은 **막대가 없는 것이 메시지**라 `0` 을 글자로 적는다. 글자 색을 쓴다 —
  막대 색을 쓰면 "작은 막대" 로 읽힌다
- 값은 **가장 비싼 안과 기존 수단에만** 적는다 (모든 막대에 숫자를 달면 표를 한 번 더 그린다)
- **라벨에 조사를 붙이지 말 것** — `기존 KTX 을` 처럼 노선 이름에 따라 은·는·을·를 이
  틀어진다. 제목은 조사 없이 쓰고 어느 수단인지는 막대 줄이 말한다

**수단별 B/C 막대(`BcChart`)** 표 위에 **모양만** 보여 준다 — 숫자는 표가 갖고 있다. 1.0
기준선 하나로 "어떤 안이 선을 넘는가"가 바로 읽힌다. 차트 하나 때문에 Recharts 를 넣지 않고
SVG 로 직접 그렸다.

- 한 계열이라 **범례 없이**(제목이 곧 계열 이름) 한 색이다. 통과·미달을 색으로 가르지 않는다 —
  기준선이 이미 그 일을 하고, 색으로 상태를 말하면 표의 경고와 역할이 겹친다
- **큰 안 몇 개가 축을 독식한다**(처음엔 BRT 6~15, 11-08 수요 보정 뒤에도 광역급행 7.0·BRT 5.5). 축을 3.0 에서 자르고 **잘린 막대에만** 값을 적는다
- 기준선은 **실선** hairline (점선은 격자처럼 읽혀 노이즈가 된다). 막대 14px, 데이터 끝만 둥글게

**인구밀도 3D(`usePopulation3D`)** 집계구 인구를 반경 300m 육각형으로 묶어 높이로 세운다
(HexagonLayer). 집계구는 크기가 제각각이라 그대로 그리면 면적이 큰 구역이 커 보인다 — 고정
크기 육각형에 모아야 **밀도** 비교가 된다 (정차역 배치가 고정 반경으로 세는 것과 같은 이유).

- **높이 축척이 함정이다.** 1명당 0.25m (95분위 기둥 약 2km). 처음 쓴 12m 는 기둥이 **98km** 로
  솟아 지도와 노선이 통째로 묻혔다. 반경 300m 칸에 서울 기준 3,000~10,000명이 모인다
- **`interleaved: true` + `beforeId: 'route-line'`** — 기본 overlay 모드는 모든 지도 레이어 위에
  그려서 노선이 기둥에 묻힌다
- 상위 1%(`upperPercentile`)는 잘라 낸다. 한 칸이 높으면 나머지가 다 눌려 보인다
- 끄면 pitch 가 0 으로 돌아가고 레이어도 떼어 낸다

**시나리오 비교(`ComparePage`)** 비교표가 한 노선 안에서 수단을 고른다면, 여기서는 **노선끼리**
견준다 — 어느 노선을 먼저 할 것인가. 개요와 수단별 B/C 표 두 개이고, 수단마다 B/C 가 가장 높은
노선을 굵게 표시한다 (**노선이 하나뿐이면 강조하지 않는다** — 전부 1등이라 의미가 없다.
**B/C 0 은 강조하지 않는다** — BRT 저급형이 세 노선 모두 0.00 동점이라 셋 다 굵어졌었다).
목록 API 는 요약만 주므로 고른 시나리오의 상세를 따로 받는다 (최대 4개).

**호수·저수지 우회는 제안만 한다 (`App.jsx` 의 `water`, 패널의 `.water-note`).** 점이 바뀌면
0.6초 뒤 `/api/route/detour` 에 묻고, 답이 오는 사이 점이 또 바뀌었으면 버린다(`key`).
**보조 기능이라 실패해도 그리기를 막지 않는다** — 안내만 사라진다. 경고(빨강)가 아니라
제안이라 차분한 색이다. 이름 뒤에 조사를 붙이지 않는다 — 「○○저수지 **위를** 지납니다」 처럼
조사가 이름이 아니라 「위」 에 붙게 쓴다. 1.5배가 가정값이라는 것을 같은 칸에 적는다.
**구조가 지하면 서버가 제안하지 않는다**(물 밑으로 지난다) — 그래서 요청에 `structure` 를 싣고
구조가 바뀌면 다시 묻는다. `key` 는 `[points, structure]` 다

**물 위 구간은 한 줄로 적는다 (`.water-span`).** 같은 우회 응답의 `waterKm` 이다 — 우회 제안이
없어도(강만 건너도) 뜬다. 50m 미만 조각은 뺀다. 「한강 1.2km」 처럼 이름 뒤에 숫자를 붙여
조사를 피한다. 교량 할증이 없다는 것을 같은 줄에 적는다 — 숫자만 있으면 "다리 값도 들어갔다" 로 읽힌다.
**지하면 「물 아래 구간」·「하저터널 할증」 으로 바꿔 적고**, 호수가 끼어 있으면 「지하라 물 밑으로
지나므로 우회를 제안하지 않습니다」 를 붙인다 — 안 적으면 지하에서 왜 제안이 사라졌는지 모른다.
**지도에도 그 토막을 파랗게 덧그린다**(`MapView` 의 `waterPieces`, 줄에 「지도의 파란 토막」). 숫자만
있으면 3km 노선의 어느 0.6km 인지 모른다. **패널과 같은 기준(50m 이상)** 으로 거르고, 점이 바뀌면
새 응답이 올 때까지 비운다(`waterNow` — 옛 노선의 토막이 새 선 옆에 남지 않게)

**산 구간도 제안만 한다 (`App.jsx` 의 `mountain`, 패널의 `.mountain-note`, 문구는 `mountainNote.js`).**
호수와 같은 틀(0.6초 · `key` · 실패해도 그리기를 막지 않음 · 훅은 이른 `return` 위)로 `/api/route/mountain`
에 묻는다. 긴 노선은 몇 초 걸린다(서울~부산 3초). **계산 전엔 길이만**(터널 km · 돌아가면 +km) — 건설비·
소요시간은 수단마다 달라서, **계산 후엔 지도에 그린 안(`shown`, 비교표에서 고른 행)** 의 단가로 두 안을
적는다. 비교표 11행에 두 안을 덧붙이지 않는다(22행이 된다). **섞지 않는 것** — 「지형 자료 없음」(흐린
한 줄)과 「산 없음」(칸이 없다), 트램의 「터널비를 모릅니다」 와 0원, BRT(도로 기준이라 판정하지 않음)와
지하(이미 땅속 — 서버가 안내하지 않는다), 「돌아갈 수 있는 구간이 없습니다」 와 「돌아가는 편이 비싸 뚫습니다」
(`costlier` — 돌 수는 있지만 손해). 돌아갈 구간이 하나도 없으면 「1.5배」 로 못박지 않는다(경유점 50개로 빠진
구간도 있다). 「돌아가기」 는 터널보다 쌀 때만 돌고 나머지는 뚫은 값이다 — 같은 칸에 적는다. 터널비가 외삽이라는 것을 같은 칸에 적는다. **지도는 갈색**(`#8b5a2b`) —
터널 토막은 노선 위 실선, 0.1km 토막은 점 하나라 동그라미, 돌아가는 안은 노선 **아래** 점선 미리보기
(실선이면 이미 바뀐 것으로 읽힌다). 전국 축척에선 갈색이 역 동그라미에 가려 흐리다 — 숫자는 패널이
말한다. 지형 출처는 그 소스의 `attribution`(「지형 © Mapzen·SRTM」)

**저장된 시나리오를 열면 지도를 그 노선에 맞춘다 (`MapView` 의 `focus`).** 전에는 시흥~안양을
열어도 지도가 서울 도심에 그대로 있었다. **`points` 가 아니라 `focus` 에 반응한다** — App 이
불러올 때만 올리는 숫자다. 점이 바뀔 때마다 맞추면 그리는 도중에 지도가 튀어 다음 점을 못 찍는다.

**이름을 모르는 정차역에는 글자를 달지 않는다 (`MapView`).** 역 이름은 반경 안 집계구의 행정동인데 집계구는
기존 역 주변으로 모은 자료라 서울~부산 중간은 비어 있다. 전에는 순번(5, 6 … 23)을 이름 자리에 찍어 **뜻 없는
숫자가 줄지어** 보였다(11-05). 순번과 이유는 툴팁에 두고, **이용객도 「0명」 이라 적지 않는다** — 모르는 것이다
(백엔드는 모를 때도 0 을 싣는다). 실제 이름을 채우려면 좌표→행정동 자료(예: 카카오 로컬 API)가 따로 필요하다

**시나리오 비교의 「이미 있는 수단」 에는 짧은 두 숫자를 붙인다** — 「164분 · 추가 건설비 0」. 이름만 있어서 무엇과
견주는지 안 보였다(11-05). 바로 아래 「추천안 소요시간」 행과 나란히 읽힌다. 노선 목록 같은 긴 설명은 여전히 툴팁이다
(칸 폭 — 위 「설명을 칸에 넣지 않는다」)

**기존 노선은 지도에 청록 점선으로 그린다 (`MapView` 의 `existing-route`).** 먼 거리를
그려 기존 KTX 가 걸리면, 두 역을 이은 선과 양 끝 점을 **그린 노선(빨간 실선) 아래에**
깐다 — 참고용이라 사용자가 그린 것을 가리면 안 된다.

- **반드시 점선이다.** 우리가 가진 것은 **두 역의 좌표뿐이고 실제 KTX 선형이 아니다.**
  실선으로 그리면 빨간 노선과 같은 급으로 읽혀 "가지도 않는 길" 을 그리는 셈이 된다
- 색은 청록(`#0f766e`) — 노선의 빨강·정차역의 파랑과 겹치지 않는다
- **`map.on('load')` 에 직접 매달지 말고 `mapReady` 상태를 쓴다.** 개발 환경은
  StrictMode 라 지도가 두 번 만들어지고, 숨겨진 창에서는 첫 프레임이 늦게 그려져
  `load` 가 한참 뒤에 온다. 이벤트 순서에 기대면 **지도가 뜨기 전에 시나리오를 연
  경우 점이 영영 안 그려졌다** — 실제로 그렇게 헤맸다
- **소스·레이어는 `style.load` 에서 만들고, 그리기는 `mapReady` 를 기다린다. `load`·`isStyleLoaded()` 는 쓰지
  않는다** — 둘 다 **타일까지 다 받았다**는 뜻이다(`SourceCache.loaded()`). 두 가지가 깨졌다(11-06, CDP `Fetch` 로
  타일 하나를 붙잡아 재현). ① 타일 하나가 안 끝나면 `load` 가 안 와 노선·산·물 레이어와 `fitBounds` 가 통째로
  멈춘다 — 축척 3 km·빨간 선 없음·「지형 ©」 없음인데 역 마커(DOM)만 보인다. 놓아 주면 1초 안에 전부 돌아온다
  ② `load` 는 지도 일생에 **한 번**이라, 그 뒤 타일을 받는 사이 시나리오를 열면 `once('load')` 로 미룬 그리기가
  **영영 안 돈다** — 이쪽은 타일이 끝내 안 오지 않아도, 그 순간 받는 중이기만 하면 난다(2초만 붙잡아 확인). 지도는 옮겨 가고 역도 찍히는데 선만 없다
- **`load` 를 `style.load` 로만 바꾸면 모자란다.** 재현 시나리오는 통과해서 고친 것처럼 보인다 — `fitBounds` 가
  카메라를 옮겨 걸린 타일이 화면에서 빠지면 `load` 가 와서 **우연히** 그려질 뿐이다. 손으로 그린 노선과 노선
  쪽 타일이 걸린 경우는 그대로 선이 없다. 걸린 타일은 빈 네모로 남고 `load`·`idle` 은 끝내 안 온다 — 거기에
  새 일을 매달지 말 것. `MapView.ready.test.js` 가 소스 모양으로 막는다
- **숨겨진 창에서 측정하지 말 것.** 지도가 아직 안 그려져 `load` 가 안 끝난 상태라
  레이어·마커가 전부 없는 것처럼 보인다. 화면을 한 번 띄운(스크린샷) 뒤에 세어야 한다

**관리자 화면은 기준값·단가·회원·통계 네 탭이다 (`AdminPage`).** 회원 표의 버튼은 `adminRules.js` 의 `userActions` 가
정한다 — 서버가 막는 일에 버튼을 주면 눌렀을 때 400 이 나고 이유를 그 자리에 못 적는다. 본인 행은 버튼 없이 안내만,
다른 관리자는 내리기만, 일반 회원은 올리기·지우기다. 삭제 확인은 **함께 사라지는 시나리오 수**를 말한다. 실패는
기준값 표처럼 그 행 아래에 적는다. 통계는 숫자 칸 + 일별 막대(한 색·범례 없음·최댓값만 표기, 빈 날은 0 으로 채운다
— 안 채우면 활동이 이어진 것처럼 보인다) + 표 안 막대다. **지금 남아 있는 것만 센다**고 같은 화면에 적는다.

**비교표 아래에 지도에 그린 안의 비용 구성·역별 예상 이용객을 그린다 (`RowBreakdown`, 값은 `breakdown.js`).** 행을 고르면
따라 바뀐다. 비용 구성은 회귀식의 세 항이지 공사 내역이 아니라고, 역별 이용객은 인구 비율로 나눈 근사라고 같은 자리에
적는다. **이름 없는 역의 0 은 「모름」** 이라 빼고 그 수를 적는다(지도의 역 표시와 같은 규칙). 구성을 모르면
(`costParts` 가 null) 차트를 그리지 않는다 — 0% 로 그리면 공짜로 읽힌다. 값 글자는 비용은 전부(셋뿐), 역은 최댓값만이다.

**단가 탭은 저장하면 행의 id 가 바뀐다 (`AdminCosts`)** — 새 행을 만들고 이전 행을 내리므로 저장 뒤 목록을 다시 받는다. 이전 값은
접힌 「이전 기준」 에 읽기 전용으로 남는다. 입력 검사(`costDraftError`)는 서버와 같다 — 문구가 있으면 그 행 아래에 적고 저장을
잠그며, 바뀐 것이 없으면 문구 없이 잠근다. 지하·고가 대소는 다른 행을 봐야 해 서버가 막는다(그 실패도 행 아래에 뜬다).
**낡은 결과 알림은 `isStale(계산 시각, 기준값 시각, standardChanged)`** — 셋째 값을 빠뜨리면 단가를 고쳐도 알림이 안 뜬다.

**이용객 한 줄은 경전철이 아닌 행의 값이다 (`demandNote.js`).** 수요 회귀가 경전철만 따로 보정해(×0.53, 11-08) 행마다 이용객이 다를 수 있다.
전에는 첫 행을 읽어, 경전철이 앞에 오면 패널 전체가 경전철 값을 말할 뻔했다. 패널(`CostTable`)과 시나리오 비교(`ComparePage`)가 같은 `baseRow` 를
쓴다. 경전철 배수는 **결과에서 거꾸로 잰다**(`lightRailFactor`) — DB 계수를 화면에 또 적어 두면 재학습 때 어긋난다. 트램은 「보정하지 않았다
(수요 자료 없음)」 로 적는다 — 「같다」 로 읽히면 안 된다. **BRT 도 보정한 수단이다** — 세종 BRT 축 실측에 맞춰 그 행만 줄인다(11-08). 기준 행(`baseRow`)에서 경전철과 함께 빼고,
배수는 `brtFactor` 로 결과에서 잰다. 처음엔 트램과 묶어 「자료 없음」 이라 적었는데 자료가 있었다. **이용객이 역 승하차 합이라는 것**도 같은 줄에
적는다 — 편익은 노선 이용자 수(×0.777)로 세는데 화면의 이용객은 승하차 합이라, 안 적으면 두 숫자를 이을 수 없다

**역 이름표는 겹치면 숨긴다 (`labelLayout.js` 의 `visibleLabels`).** 지도가 멈출 때(`moveend`)마다 화면 위치를 재고, 이용객이 많은 역부터
놓아 이미 놓인 것과 4px 안으로 붙는 이름표는 `visibility: hidden` 으로 숨긴다 — `display: none` 이면 자리가 사라져 다음에 못 잰다. 같은
우선순위는 앞쪽 역이 이겨 매번 같은 답이다(안 그러면 지도를 움직일 때 깜빡인다). 숨긴 역도 점은 남고 마우스를 올리면 이름이 보인다.
서울~부산은 61개 중 17개가 보인다(11-08) — 전에는 양 끝에서 전부 겹쳐 하나도 읽을 수 없었다.

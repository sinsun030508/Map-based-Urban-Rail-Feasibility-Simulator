# 실제 대중교통 경로 비교 (하단바) — 설계

2026-11-28. 상태: **승인·구현됨**(같은 날, 로컬 화면 확인까지 — EC2 에는 아직).

## 의도

그린 노선의 양 끝을 **지금 있는 대중교통**으로 가면 어떻게 되는지를 지도 아래에 카드로 보여, 신설안과 바로 견주게 한다.
사용자가 준 본보기는 지도 앱의 경로 목록(소요시간 + 도보 → 버스 511 → 1호선 → 버스 501 → 도보)이다.

## 목표 / 하지 않는 것

- 목표: 실제 버스 번호·지하철 노선·도보 구간이 든 경로 최대 3개와 신설안 1개를 한 자리에서 본다.
- 안 한다: **B/C·편익·추천 규칙을 바꾸지 않는다**(`CalculationRules.CHANGED_AT` 그대로). 경로 결과를 DB 에 저장하지 않는다.
  도착 예정 시각 같은 실시간 정보를 흉내 내지 않는다.
- **바뀐 것(같은 날 사용자 요청)**: 처음엔 「지도에 대중교통 경로를 그리지 않는다」 였다 — 이제 상자를 누르면 TMAP 이 준 좌표로 그린다.
- 실패로 볼 것: 신설안과 실제 경로를 **다른 기준의 숫자로 나란히 놓고 차이를 말하는 것**, 키가 브라우저나 저장소에 드러나는 것,
  사용자가 모르게 호출 한도를 쓰는 것.

## 제약 (11-28 공식 페이지 확인)

- TMAP 대중교통 API `POST https://apis.openapi.sk.com/transit/routes` — 인자 `startX`(경도)·`startY`(위도)·`endX`·`endY`·`count`·`searchDttm`.
  응답 `metaData.plan.itineraries[]` — `totalTime`(초)·`totalWalkTime`·`transferCount`·`fare.regular.totalFare`·`legs[]`(`mode`
  WALK·BUS·SUBWAY·EXPRESSBUS·TRAIN·…, `sectionTime`, `route`, `routeColor`, `start.name`, `end.name`, `service`).
- 무료 **하루 10건**, 넘으면 자동 차단. 종량제 0.88원/건. ([요금](https://transit.tmapmobility.com/))
- TMAP 약관: 얻은 데이터는 **저장 후 24시간 이상 쓸 수 없다**. ([약관](https://tmapapi.tmapmobility.com/terms.html))
- 프로젝트 규칙: 추정값을 넣지 않는다. 비밀값은 `.env` 에만, 기본값 없음.
- **실제 호출 1건으로 확인(11-28 23시, 서울시청→잠실, `searchDttm` 은 다음 월요일 08:00)** — 200, 경로 3개. `totalTime` 은 구간
  `sectionTime` 의 합과 같다(대기 항목이 따로 없다 — 구간 시간에 대기가 드는지는 모른다). 대체 노선은 **`Lane`**(대문자 L)에 온다.
  대표 노선 `service` 0 인데 `Lane` 의 급행은 1 인 구간이 있었다. 운행하지 않는 심야버스(`service` 0)도 경로 목록에 남는다.
- **`searchDttm` 은 운행 여부에 적용된다**(11-28 두 번째 호출, 같은 구간 평일 03:00 — 모든 구간 `service` 0). **경로 목록·소요시간은
  거의 같았다**(48·54·81분 ↔ 08:00 의 48·55·81분). 그래서 화면 문구는 「운행 여부는 평일 08:00 기준」 이다.
- **아직 확인 못 한 것**: SK open API 약관의 출처 표기 의무, 「경로 없음」·한도 초과 때의 응답 모양.
- **따라서**: 대표 노선이 0 이어도 `Lane` 에 1 인 노선이 있으면 그 노선을 보인다. 대안까지 전부 0 인 구간이 든 경로는 뒤로 보내고
  「운행 안 함」 을 적는다. **시험 자료는 손으로 만든다** — 실제 응답을 저장소에 넣으면 24시간 저장 제한에 걸린다.

## 방법

| 안 | 맞바꾸는 것 | 결정 |
|---|---|---|
| 우리 계산값 카드(기존 수단 한 줄·시내버스 추정) | 바로 되지만 버스 번호·환승이 없다 | 사용자가 실제 경로를 원했다 |
| 서울시 대중교통환승경로(공공데이터) | 무료 1,000건/일, 서울 중심 | 전국 노선에 안 맞는다 |
| **TMAP 대중교통** | 전국·노선 번호·색, 무료 10건/일 | **사용자 선택(11-28)** |
| ODsay | 30건/일, 비상업용·저장 금지, IP 등록 | 서버 IP 가 바뀐다 |

## 화면

지도 아래쪽에 겹쳐 놓는 접히는 바. 계산 결과가 있고 서버에 키가 있을 때만 버튼이 보인다. **누를 때만 호출한다.**

```
┌ 지금 있는 대중교통과 비교 · 평일 08:00 기준 · TMAP                      [접기] [닫기] ┐
│ [신설 광역급행] 역~역 18분              ████ 광역급행 18                             │
│                 걷기·대기 제외                                                       │
│ [실제 경로 1]   52분 (걷기 12분) 환승 2  ▒도보▒ ■511■ ■■1호선■■ ■501■ ▒도보▒        │
│ [실제 경로 2]   58분 (걷기 9분)  환승 1  ▒도보▒ ■■■수인분당선■■■ ■3500■ ▒도보▒      │
└──────────────────────────────────────────────────────────────────────────────────┘
```

- 신설안 카드는 **지도에 그린 안**(`shown`, 표에서 고른 행)을 따른다. 소요시간은 지금 표의 값 그대로이고 「역~역 · 걷기·대기 제외」를 붙인다.
- 실제 경로 카드: 총시간과 그중 걷기, 환승 횟수, 요금, 구간 칩(노선 색, 폭은 구간 시간에 비례하되 글자가 읽히는 최소 폭).
- **차이(「몇 분 빠름」)는 적지 않는다** — 기준이 다르다. 걷기를 뺀 시간을 보조로 적는다(「걷기 빼면 40분」). 대기가 드는지 확인되면 문구에 반영한다.
- 운행하지 않는 구간(`service` 0)은 칩에 「운행종료」를 적는다.
- 좁은 화면에서는 바 안을 세로로 스크롤한다. 지도 조작을 막지 않는다.

## 동작

- 출발·도착은 **찍은 첫 점과 마지막 점**이다(종점역이 아니다 — 사람이 가려는 곳).
- 기준 시각은 **다음 평일 08:00** 하나다(설계자 판단: 밤에 조회하면 막차·심야버스가 섞이고, 프로젝트가 평일 첨두를 본다).
  `searchDttm` 이 경로에 영향이 없다고 확인되면 시각 문구를 빼고 운행 여부 표시도 뺀다.
- 점이 바뀌면 바를 비운다(옛 노선의 경로가 남지 않게). 저절로 다시 부르지 않는다.

## 백엔드

- `POST /api/route/transit` (로그인 필요). 요청 `{from:{latitude,longitude}, to:{…}}`.
  응답 `{status: OK|DISABLED|LIMIT|NO_ROUTE|FAILED, searchedFor, itineraries[최대 3]}` — 화면이 쓰는 칸만 옮긴다.
- `TMAP_APP_KEY` 가 비면 `DISABLED`(버튼 숨김). 앱은 그대로 뜬다.
- **하루 호출 상한** `TMAP_DAILY_LIMIT`(기본 10) — Redis 로 센다. 종량제로 바꿔도 모르게 쓰이지 않게. **Redis 가 죽으면 부르지 않는다**
  (로그인 제한과 반대 — 여기는 돈과 한도가 걸린다). 날짜는 한국 시간으로 가르고, 캐시에서 꺼낸 답은 세지 않는다.
  기준 시각의 「평일」은 월~금이다(설계자 판단: 공휴일은 가리지 않는다).
- **같은 요청은 12시간 Redis 에 담는다**(좌표 소수 5자리 + 기준 시각) — 한도를 아끼고 24시간 약관 안이다. 성공과 「경로 없음」만 담는다.
- 타임아웃 8초. 실패해도 계산·그리기에 영향이 없다. 키는 로그에 남기지 않는다.

## 설정·문서

`.env.example`(자리표시자), `docker-compose.deploy.yml`(`TMAP_APP_KEY`·`TMAP_DAILY_LIMIT`), `application.yml`, `docs/deploy.md`,
`CLAUDE.md`·`frontend/CLAUDE.md` 의 규칙 한 줄. 화면 CSP 는 그대로다(브라우저는 우리 서버만 부른다).

## 시험

- 백엔드: TMAP 응답 모양의 고정 자료로 변환·상한·캐시·키 없음·Redis 장애. **테스트는 실제 API 를 부르지 않는다.**
- 프론트: 시간·구간 표기와 차이를 말하지 않는 규칙, 점이 바뀌면 비우기.
- 실제 호출 확인은 사용자 키로 **하루 한도 안에서 몇 번만**(첫 호출 응답을 보고 위 「확인 못 한 것」을 닫는다). 화면은 직접 열어 본다.

## 사용자가 할 일

SK open API 가입 → 앱 만들기 → 「TMAP 대중교통」 무료 상품 사용 신청 → 앱 키를 `.env` 의 `TMAP_APP_KEY=` 에 적기(채팅에 붙이지 않는다).

## 만드는 사람에게 맡기는 것

클래스·컴포넌트 이름과 나누기, 칩의 정확한 크기·색 대비(노선 색 위 글자), 바의 높이.
